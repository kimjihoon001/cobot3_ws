### MoveIt 백엔드 주의 (혼동 방지)
수확 FSM은 `rmp_target`/`rmp_home` JSON 명령을 발행하지만, **이름만 옛 RMPflow 잔재**다. 실제 소비부 `mm_motion_bridge.py`가 이를 **MoveIt MoveGroup 액션 + compute_ik(pilz PTP/OMPL)**로 변환한다. 즉 **완전히 MoveIt**이다. `rank_approach_ik`, `_start_ranked_approach_ik`, compute_ik 다중 seed 최소변화 IK 선택이 핵심.

## 2. 이번 세션 변경사항 (파일별)

### A. IW 주행·도킹
- **`src/smartfarm/iwhub_control/iwhub_control/mission_nav_node.py`**
  - 도킹 목표점을 `MM +X 고정 1.6955m`(=베드 방향) → **`MM 중심 + (MM→IW 접근방향) × dock_standoff`**로 변경.
  - `follow_offset_x/y` 제거, **`dock_standoff`(기본 1.2m)** 파라미터 추가.
  - 이유: 기존 오프셋이 IW를 베드 안으로 보내 충돌.
- **`src/smartfarm/iwhub_control/config/nav2_params.yaml`**
  - local/global **footprint 앞/뒤를 실제 라이다 프레임(+0.65 / -1.08)까지 확장**(폭 ±0.401 유지).
  - 이유: 라이다(스캔 원점)가 기존 footprint(+0.3975/-1.0335) 밖으로 튀어나와 MM과 충돌 판정이 어긋남.
- **`src/smartfarm/iwhub_control/launch/iwhub_nav2.launch.py`**
  - (1) localization(map_server+amcl) include를 **`TimerAction(2.0s)`로 지연**(navigation 3s보다 먼저).
  - (2) **`nav2_lifecycle_activator`를 IW 네임스페이스에 추가**, `targets=[map_server, amcl]`, `startup_delay_sec=3.0`.
  - 이유: IW map_server가 FastDDS service 응답 유실로 **activate 실패 → /iwhub_0/map 미발행**. activator가 실제 state 재확인하며 재시도해 확실히 활성화.
- **`src/smartfarm/fleet_dispatch/fleet_dispatch/nav2_lifecycle_activator.py`**
  - `targets` 파라미터 추가(담당 lifecycle 노드 지정). 기본은 기존 전체 목록.

### B. MM 플레이스·바스켓
- **`isaacpjt/iw.py`** — `_publish_empty_basket_pose`
  - 첫 유효 슬롯(KLT_01, 데크 뒤쪽) 고정 발행 → **데크 로컬 x가 가장 큰(=IW 코=MM 쪽) 빈 슬롯** 발행.
  - 이유: KLT_01은 MM에서 1.9m(도달 밖). 앞쪽 KLT_31은 MM에서 ~0.98m(도달 가능). MM prim 조회가 불안정해 **데크 로컬 x 기준**으로 견고하게 선택.
  - 데크 배치: 4×2, x간격 0.31 / y간격 0.25. 빈칸 후보 `KLT_01,10,20,21,31`. 앞쪽=KLT_31(ix=3).
- **`src/smartfarm/harvest_vision/harvest_vision/manipulator_target_node.py`**
  - `basket_workspace_min` X **`-0.80 → -1.05`** (m0617 리치가 UR10e보다 길어 MM 뒤쪽 슬롯 도달 가능).
  - **바스켓 중심 보정**: `_start_place`에서 release 목표를 **MM 쪽(수평 반경 안쪽)으로 `basket_place_toward_mm_m`(기본 0.06m) 당김**. 이유: 릴리즈가 목표보다 바깥에 떨어져 옆 칸 사이에 놓임.

### C. MM 수확 안정화 (재시도 / 좌표 안정화)
- **`manipulator_target_node.py`**
  - **실패 재시도 3단계**(`_abort_to_home`):
    1. `approach_retry_max`(1): APPROACH 안전점으로 후퇴 후 **동일 표적** 재파지.
    2. `bed_view_retry_max`(1): 소진 시 `_send_home(retry_after_home=True)` → RETRY_VISION → **베드뷰 재관측 후 새 표적** 가능.
    3. 모두 소진 → 최종 홈 복귀(사이클 실패). 파지 성공(`_begin_cut`) 시 카운터 리셋.
  - **타겟 5프레임 고정 게이트**: `_target_callback`에서 좌표가 `target_stable_eps_m`(0.01m) 이내로 `target_stable_frames`(5) 연속 안정돼야 `WAIT_TARGET→시작`. 베드뷰 재관측에도 동일(재관측 시 카운터 리셋).
- **`nav_harvest_test_node.py`**
  - 코디네이터 `RETRY_VISION` 처리를 `_start_search`(홈 카메라) → **`_begin_post_nav_home()`(홈→베드뷰 재관측)**로 변경.

### D. MM 팔 속도 / 플레이스 모션
- **`src/smartfarm/mm_moveit/scripts/mm_motion_bridge.py`**
  - 속도 상향: `_pose_goal` per-motion dict **OMPL 0.20→0.35, PTP 0.25→0.40, LIN 0.08→0.15, CIRC 0.10→0.15**. `velocity_scale`(홈·조인트) 0.30→0.50, **`acceleration_scale`(0.30) 파라미터화**(기존 0.15 하드코딩 대체).
    - GRASP(0.05)·CAPTURE_TRIM(0.035)은 명시 오버라이드라 **저속 유지**(정밀도 보존).
  - **BASKET_APPROACH를 랭크드 IK로**: 게이트를 `phase in (APPROACH, BASKET_APPROACH)`로 확장. **basket 전용 IK 가중치 `basket_ik_joint_change_weights=[0.3,3.0,3.0,3.0,4.0,4.0]`**(joint_1 싸게=회전 허용, 나머지 비싸게=고정) → 방향만 joint_1 회전으로 맞추고 다른 관절 최소.
- **`manipulator_target_node.py`** `_send_rmp_goal`: BASKET_APPROACH motion을 PTP → **OMPL**(랭크드 IK 경로 진입).

## 3. 주요 진단 결론 (rosbag 기반)
- **IW 베드 충돌**: 센서·자기반사 필터·costmap 마킹은 **정상**. 진짜 원인은 (1)FOLLOW가 IW를 베드 안(MM+X)으로 보냄, (2)닿아도 멈추는 장치 없음(controller 바퀴만 헛돎 "Failed to make progress"). → 도킹 방향 수정으로 해결.
- **MM 충돌**: 도킹은 됐으나 footprint가 라이다보다 짧아 MM과 접촉. → footprint 확장.
- **슬롯 미도달**: 앞쪽 KLT_31은 MM base X≈-0.95, r≈0.98(도달 가능)인데 작업영역 box X_min=-0.80이 막음. → box 완화 + 앞쪽 슬롯 선택.
- **IW 맵 미발행**: map_server가 **configure만 되고 activate 실패**(FastDDS service 응답 유실). map_server 전이 이벤트 0~2회(MM은 4회=완전 활성). → activator 추가.
